## 1. Alerta
O Wazuh registrou um **uso de sudo bem-sucedido** para executar um comando sensível: a leitura de `/etc/shadow` (arquivo que guarda os hashes de senha). Regra 5402.

## 2. Investigação

1. `agent.name` = noc-lab.
2. `rule.id` = 5402; `rule.level`.
3. `full_log` → qual usuário rodou o sudo e **qual comando** (a leitura de `/etc/shadow`).
4. O usuário tinha autorização? O comando é compatível com a função dele?

## 3. IOCs
Nenhum IOC de malware. O ponto de atenção é **o comando executado** e **o usuário** que o rodou.

## 4. Mapeamento MITRE ATT&CK
- **Tática:** Privilege Escalation (TA0004)
- **Técnica:** T1548 – Abuse Elevation Control Mechanism (uso de sudo)
- **Por quê:** ler `/etc/shadow` é um passo típico de quem quer **extrair hashes de senha** para quebrar offline. Mesmo com sudo legítimo, o *que* foi feito importa.

## 5. Resposta
Simulação, sem ação. Em um caso real: confirmar se o usuário podia fazer isso. Se não, tratar como **tentativa de roubo de credenciais** — escalar para Segurança, revisar o que a conta fez antes e depois.

## 6. Lições aprendidas
- Nem todo sudo é problema; o que vale é **qual** comando foi rodado. Ler arquivos de senha, parar serviços de segurança ou instalar pacotes merecem olhar.
- Vale configurar o Wazuh para alertar com nível mais alto em comandos sensíveis específicos.
